# Аудит генерации мира LCEReborn

Проверка выполнена на текущем рабочем дереве с изменениями Village & Pillage. Для запуска использована нативная Windows-сборка. Тесты создают отдельные тестовые миры и используют штатный код генерации, размещения и чтения сохранений.

## Резервная копия

`C:/Users/hetem/LCEReborn-worldgen-backup-20261128-004950`

Снимок сделан перед расширенным аудитом, после начала исправления деревень по предыдущему запросу. Скопировано 9 099 файлов, включая `.git`, незакоммиченные и новые исходники, ресурсы и каталог сохранений рабочего дерева. Сравнение `git status` показало одинаковые 287 изменённых и новых файлов. Каталог `build` содержит промежуточные сборки и результаты тестов и исключён из снимка.

## Деревни Village & Pillage

| Проблема | Исправление |
| --- | --- |
| При планировании высота иногда считывалась из соседней колонки. Сдвиг был общим для деревень, особняков, городов Края и кораблекрушений. | `ChunkPrimer` теперь обращается к колонке по координатам её состояния блока, включая верхнюю секцию. Для фундаментов поверхность суши и слой жидкости определяются отдельно. |
| Дом мог быть принят по высоте у входа, хотя остальной фундамент попадал в склон или воду. Подготовка площадки вырезала всю колонку над полом и засыпала полости до первого твёрдого блока. | Планировщик проверяет весь нижний ряд конструкции. Дороги следуют уклону с перепадом до одного блока между соседними колонками. Крутой или затопленный участок может быть отклонён. Штатный поиск использует тот же планировщик, чтобы пропустить такие участки. Работы ограничены опорами под блоками и проходом над дорожкой. |
| Вертикальные соединения домов с шаблонами жителей расходовали лимит глубины дорожной сети. Декорации и дороги могли составить формально допустимый план без жителей. | Вертикальные соединения обрабатываются на глубине родительской секции. Для действительной нативной деревни нужен шаблон обычного жителя или жителя-зомби для заброшенного варианта. |
| Java-атрибуты задавались через `Name`. Загрузчик LCE читал отсутствующий `ID` как ноль и перезаписывал максимальное здоровье значениями других атрибутов. В воспроизведённом случае все четыре жителя создавались с нулевым здоровьем. | Импорт понимает числовые идентификаторы LCE и известные имена Java. Неопознанные записи пропускаются. Шаблоны, содержащие только сущности, сохраняют блоки площадки. Жители размещаются в проходимой точке с опорой без жидкости и сохраняют уникальную идентичность. |

## Общие механизмы и структуры LCE

| Область | Найдено и исправлено |
| --- | --- |
| Координаты и повороты | Размер вращаемого шаблона и ограничивающий объём теперь вычисляются одним преобразованием с включёнными крайними блоками. Иглу учитывает основание, шахту и подвал. Для города Края высота измеряется в направлении фактического поворота. Кораблекрушение привязывает повёрнутый шаблон к границам планируемой позиции. |
| Поверхность | Иглу, храм в джунглях и хижина берут высоту всей площадки при планировании вместо той части, которую первой задел загруженный чанк. Этот же замер используется для планов океанских руин. Особняки используют высоту твёрдой поверхности. |
| Размещение по чанкам | Океанские руины нарезаются по границам обрабатываемых чанков. Выбор слоёв шаблона, подсыпки и семени добычи привязан к позиции. Поиск опоры для клада ограничен высотой мира. |
| Сохранение планов | Особняк восстанавливает действительность по загруженным секциям. Зарегистрирована загрузка городов Края, океанских руин, элементов кораблекрушений и кладов. Для крепости и адской крепости восстановлены правильные стартовые элементы. Крепость связывает стартовый элемент с комнатой портала после чтения. |
| Устойчивость загрузки | Версия чтения плана локальна для потока. Запись с неизвестной секцией отвергается целиком, поскольку старый формат не позволяет безопасно пропустить такую секцию. Копии настроек шаблона владеют собственными границами. |
| Порядок и генераторы случайных чисел | Пересекающиеся планы попадают в обработку в координатном порядке. Восстановление плана монумента использует собственный генератор случайных чисел и не расходует последовательность декораций чанка. Смешивание сида и координат использует явно заданное переполнение беззнаковых чисел. |
| Состояния, жидкости и добыча | Проверены повороты состояний и нативные представления двойных и верхних плит, а также блоков с водой. Таблица добычи вагонетки теперь сохраняется по своему NBT-полю независимо от версии последнего прочитанного плана структуры. |
| Управление ресурсами | Исправлено освобождение массивов кеша чанков и секций удалённого плана. Отсутствующий архивный шаблон повторно использует пустой экземпляр. |

Новые записи планов используют версию 5. Она хранит дополнительные координаты иглу, размеры и поворот океанских руин, а также параметры шаблонов восстановленных типов структур. Для полей старых записей сохранены ветки чтения по версии формата.

## Матрица испытаний

Основные сиды — `1`, `-90210` и `987654321`. Отдельная проверка нативных деревень охватывает пять сидов и шесть биомов. Для узких сценариев биом задаётся тестом, а форму рельефа генерирует штатный генератор.

- Обычный мир, Нижний мир и Край — создание соседних чанков в обоих порядках, сравнение состояний блоков и карт высот. В этот проход входят стадии подготовки рельефа и доступные для измерения карверы.
- Отдельные сценарии проверяют отбрасывание затопленного участка и площадки с резкими перепадами высот, а также поиск деревни в затопленном мире.
- Многократное чтение и запись плана — деревня, лесной особняк, шахта, крепость, пустынная пирамида, храм в джунглях, хижина ведьмы, иглу, монумент, океанские руины, кораблекрушение, клад, адская крепость и город Края.
- Деревни и особняки — размещение на сгенерированном рельефе, переход через границы чанков, продолжение после чтения частично размещённого плана, проверка обитателей и сундуков.
- Отдельная загрузка тестовых чанков проверяет двоичный кодек LCE. Для саванной деревни на сиде `1` чанк также записан и прочитан через хранилище регионов после очистки кеша регионов. Тесты работают с изолированными сохранениями.
- Нативные деревни — сверка 482 шаблонов, 61 пула, сущностей, состояний и идентификаторов добычи. Пользовательские шаблоны — импорт обычного и gzip NBT, отсев повреждённых записей и продолжение размещения после загрузки.

| Сид | Саванная деревня — изменившиеся чанки, живые жители, сундуки с добычей | Особняк — изменившиеся чанки, живые обитатели, сундуки с добычей |
| --- | --- | --- |
| `1` | 26, 4, 4 | 30, 16, 2 |
| `-90210` | 34, 4, 2 | 28, 16, 5 |
| `987654321` | 33, 8, 4 | 28, 23, 4 |

Житель или обитатель особняка в контрольном чанке пережил сохранение и повторное чтение в каждом из шести сценариев. На сиде `1` отдельный прогон с включёнными структурами нашёл деревню в чанке `(5, 6)` штатным поиском. При обычной генерации в ней появилось восемь живых жителей.

Физическое размещение остальных 12 типов проверено отдельным прогоном на сиде `1`. В нём план сначала читается из сохранения, затем его части размещаются в обратном порядке чанков. Количество изменившихся чанков — шахта 41, крепость 41, пустынная пирамида 6, храм в джунглях 2, хижина 1, иглу 1, монумент 25, океанские руины 7, кораблекрушение 4, клад 1, адская крепость 79, город Края 29. В каждом случае найдены характерные блоки структуры.

Основной прогон занял около 13 с после инициализации игры на этой машине. Измерено время всего теста. При повторном запуске в отдельном процессе совпали сводки размещения и количество секций во всех планах. Клиент и выделенный сервер собраны для Windows. Все четыре набора проверок завершились с кодом 0.

Исходник проверок — [worldgen_runtime_check.hpp](../tools/tests/worldgen_runtime_check.hpp). Протоколы запусков находятся в `build/worldgen-audit`, `build/worldgen-placement`, `build/worldgen-village-audit` и `build/worldgen-custom-audit`.

## Границы проверки

- Набор тестов охватывает выборочные сиды, шаблоны и границы чанков. Побайтное совпадение всей постобработки при любом порядке открытия чанков не установлено. Растительность и процедурные декорации деревень могут обращаться к соседним чанкам.
- Проверены тестовые миры Windows. Длительные прогоны, другие платформы, весь набор пресетов Superflat, импорт старых пользовательских миров и полная повторная загрузка пользовательского контейнера сохранения не проверялись.
- Проверка существующих проблемных деревень требует сида и копии соответствующего сохранения. Исправления планирования действуют при новой генерации.
